# Adex 员工组织与协作：第一版设计

状态：设计草案，尚未实现或验收。2026-11-06。

## 产品

用户是组织的唯一所有者，可以继续直接与现有 Agent 对话。用户创建员工，设置名称、职责、指令、所属组和直属上级；助理是可配置的协调角色，帮助拆解任务、建议分派、跟进和汇报。组织树禁止循环，同一员工至多一个直属上级。员工和组的调整不删除历史任务与消息。

会话包括用户与 Agent 的原有会话、员工私聊和群聊。员工会话及其参与者、消息、工具活动、任务关联和时间对所有者可见；员工之间的“私聊”只是参与者范围，不对所有者隐藏。群聊由所有者创建并指定参与者；消息清晰标记发送者。第一版须限制自动回复轮数和预算，避免员工互相无限对话。不可把模拟消息、任务建议或模型文本当成已完成的真实工作。

## 执行与边界

App 拥有组织、成员、会话和消息的权威数据及鉴权；Automation 拥有后台委派、运行、租约、fencing 和结果回流；Agent 承载 Codex runtime；Tools 仍负责授权、设备操作和副作用账务。员工是角色与权限配置，不是新的业务服务或独立用户账户。跨员工共享信息必须有明确范围；L3 记忆保留来源、用户纠正、删除和防复活语义，不能把 Codex 线程当作权威记忆。

助理的任务分派需要持久的任务关联和可追踪状态；外部动作沿用现有审批与幂等协议。任务执行失败、等待审批、设备离线、不可用模型和未知副作用均需明确呈现，不得冒充成功。普通用户对话继续走 App → Agent，不强制经过 Automation。

## 第一版验收

- 用户能创建和编辑员工、组和上下级，拒绝跨所有者引用及循环层级。
- 原有直接对话不回归；所有者能创建员工私聊和群聊，查看有发送者身份的完整记录。
- 员工回复使用真实配置的运行时，具备明确的参与者上下文、预算和停止条件；失败可见。
- 助理可以创建可追踪的任务建议和查看现有任务进度；只有持久执行成功才显示完成。
- 客户端展示组织、会话、任务与待审批，支持手机安全区、弱网恢复及未知卡片降级。
- 单用户免登录体验仅可在明确隔离的本地开发模式启用；公网仍须设备绑定和鉴权，不能把个人使用等同于匿名访问。
- 自动化测试覆盖所有权、层级循环、消息持久化、重复提交、会话可见性、执行失败与停止；涉及后台运行时补充租约和故障恢复测试。设备及真实供应商分别验收。

## 参考与分阶段

飞书的消息、日程与任务统一入口可作为组织体验参考：[飞书界面](https://www.feishu.cn/hc/en-US/articles/968054622804-step-2-get-to-know-the-feishu-interface)。Codex app-server 提供线程、事件与审批交互，但不能替代 Adex 的授权和持久状态：[Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)。

先完成组织和可见会话的数据契约与基础交互，再接入真实员工执行和受控协作，最后完成 SwiftUI 客户端、设备操作与部署验收。每个阶段须标明真实能力和外部阻塞，不以界面占位代替功能。
